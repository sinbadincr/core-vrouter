minivr architecture

Phase 1: a single-node lab and minivrd, a single-threaded C17 L3 forwarder modelled on Tungsten Fabric's vRouter, plus the vrctl CLI. Source of truth: specs/001-lab-l3-forwarder/ (spec, plan, research, contracts).

1Lab topology

Every "VM" is a network namespace linked to the compute node by a veth pair. The ports in mvr-cn1 carry no IP address and IP forwarding is off, so the kernel neither routes nor answers ARP. Every frame goes through minivrd.

2Inside minivrd

One process, one thread, one epoll loop. The forwarding logic in dp/ makes no system calls, so it can be unit-tested with a fake clock and a fake I/O backend.

ModuleResponsibility
pkt_eth.cEthernet classify, L2 checks; non-ARP broadcast/multicast dropped
pkt_arp.cARP validate, proxy reply for known neighbours, build ARP requests
pkt_ipv4.cIPv4 validate (length, IHL, checksum, fragments), TTL decrement, checksum update
pkt_icmp.cEcho reply; build unreachable, time exceeded, fragmentation needed
antispoof.cDrop IPv4/ARP whose source IP/MAC does not match the ingress port's binding
route.c + lpm_trie.cConnected, /32 host and static routes; longest-prefix match on a binary trie
neigh.cOpen-addressing hash table, neighbour state machine, hold queue (≤ 3 packets), ARP retry/expiry
ratelimit.cToken bucket for ICMP errors, one per ingress port
stats.cPer-port counters, per-drop-reason counters, event counters

·Fixed capacities

All tables are sized at start-up and never grow. A full table rejects CLI changes with an error; neighbours learned while the table is full are counted, not stored.

3Packet path (one burst)

Run-to-completion: each received frame goes through these checks, then the transmit batches are flushed per egress port. Every drop increments exactly one named reason.

4Example: vm1 pings vm2

vm1 and vm2 are in the same /24 but on different ports, so the forwarder answers ARP on vm2's behalf and routes the packet. There is no L2 bridge between them.

5Control path

The CLI and the start-up config share one command grammar and one parser. Because there is a single thread, a command is applied between two bursts: no locks, no RCU, and forwarding never stops.

7Relation to Tungsten Fabric

minivr rebuilds, at small scale, the part of Tungsten Fabric (TF) that runs on every compute node: the vRouter forwarder. Phase 1 builds only that part, on one node. The TF controller and vrouter-agent are replaced by a static config file that pre-loads what they would normally push down.
